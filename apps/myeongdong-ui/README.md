# 명동 3D 화면 — Rust 엔진 실험 재생

> 이 소스 브랜치에는 데이터와 지도·글꼴·재생 자산을 포함하지 않는다. 화면 빌드와 실행에는 [루트 README](../../README.md)에 적은 누락 파일을 별도로 복원해야 한다. 아래 명령은 필요한 자료가 복원된 환경에서만 동작한다.

명동 OSM 지상 보행망과 건물 자료를 사용하는 Rust 엔진을 화면에서 실행하고 결과를 재생한다. 65,000개 합성 서울 페르소나 중 서로 다른 **5,044개**를 선택해 14:00~17:00에 한 번씩 균등하게 직접 입장시킨 실험이다. 화면 인원은 해당 프레임에 표시된 인원이고, 현재까지 입장은 재생 시점까지 투입된 인원이다. 5,044명 전부가 동시에 거리에 있다는 뜻은 아니다.

**실측 방문자 또는 수요 예측이 아니다.** 원문 행동 특성은 아직 추출하지 않아 나이·직업 등 구조화 정보와 기본값을 사용한다. 지하 연결망은 제외했고, 업종을 연결한 건물 161개는 장소 대리값이다. 개발용 정의와 평면 GLB 지면을 사용하며 인물 기호는 알아보기 쉽도록 확대했다. 기존 엔진 검증 중 보행 폭·밀도와 대기열 보존 테스트 2건이 실패해 물리 결과는 검증이 끝나지 않았다. 건물별 지표는 연결된 대리 상점의 실험 기록이며 실제 매출·유동인구가 아니다. 입력·건물 종류는 실측이 아니라 시나리오 가정이다.

## 화면에서 실행

Node.js 24, 잠금 의존성과 Python 3 및 별도 `memguard` 실행 파일을 사용한다. 설치 및 준비는 [루트 README](../../README.md)를 참고한다. 작업공간 루트에서 각각 별도 터미널로 실행한다. 서버는 모두 이 컴퓨터의 `127.0.0.1`에만 열린다.

```bash
python3 scripts/myeongdong_ui_server.py --input /path/to/prepared-5044-input --memguard /path/to/memguard --port 5174
```

```bash
pnpm -C apps/myeongdong-ui dev --host 127.0.0.1 --port 5173
```

브라우저에서 `http://127.0.0.1:5173/`을 연다. 왼쪽 조건을 바꾼 뒤 **시뮬레이션 실행**을 누르면 새 계산이 시작되고, 프레임이 생성되면 새 주소로 전환된다. 조건 편집만으로는 계산하지 않는다. 두 서버가 켜져 있는 동안 로컬에서 접근할 수 있다. `memguard`와 Rust/Cargo의 오프라인 의존성이 필요하며 실행마다 현재 소스를 빌드하고 실행 전용 바이너리와 해시를 보관한다. 소득 배율 변경에는 별도 원본 데이터와 입력 번들에 기록된 사양 해시가 필요하다. 현재 포함된 사양은 그 해시와 다르므로 추가 복원 없이 사용할 수 없다.

원본 16개 항목 중 보행 전용 시간, 보행 폭, 노점 수, 벤치 수, 할인율, 영업 종료 연장, 인물 소득, 상품 가격, 시계성·옥외 광고를 엔진 입력에 반영한다. 기준 노점은 40개라는 가정이며 영업 연장은 14~17시 창에 영향을 주지 않을 수 있다. 입장 수 고정과 충돌하거나 월 단위 모형이 없는 배차·수요·외국인 유입·경쟁 상권·임대료·행사·인건비 7개는 화면에서 숨긴다. 실행 중에도 다음 조건을 편집할 수 있다. 변경은 초안으로 남고 계산이 끝난 뒤 사용자가 실행을 눌러야 적용된다. 초안은 열린 탭에서만 유지된다.

건물을 선택하면 카페·음식점·옷가게·편의점·의료 시설을 각각 지정하고 할인·가격·영업시간을 전체 값과 다르게 설정할 수 있다. 새 건물은 인근 보행망에 가정 장소로 연결한다. 지도 전용 건물은 중심 위치를 추정하며 외곽·장애물은 검증하지 않았다. 보행망에서 80m를 넘는 건물은 화면 색만 바뀌고 엔진에 반영되지 않는다. 의료 시설은 일반 방문 대리 장소이며 진료나 의료 매출 모델은 없다.

계산 중에는 완료된 프레임만 표시한다. 완료 후 엔진 사건 기록을 10분 지표와 대조한 장소 입장·구매·구매액이 나타난다. 건물을 선택하면 매칭된 대리 장소의 3시간 기록을 보여 주며, 매칭되지 않은 건물은 수치를 만들지 않는다. 기록은 실측이나 월간 매출 예측이 아니다.

```bash
pnpm -C apps/myeongdong-ui typecheck
pnpm -C apps/myeongdong-ui test
pnpm -C apps/myeongdong-ui build
```

## 검증된 가설 시연

`http://127.0.0.1:5173/demo/index.html`에서 동일한 고정 엔진과 5,044명 입장 계획으로 비교한 사례를 볼 수 있다. 두 시드의 결과와 모든 후보를 표시한다. 과거 실행 기록은 이 저장소에 포함하지 않아 기준·변경 기록 재생 링크는 해당 기록을 별도로 복원해야 동작한다. 건물 사례는 밀레오레 명동을 자동 선택한다. 자료는 합성 실험이며 과거 고정 엔진 버전의 결과다. 사용자가 다시 실행하면 현재 소스의 결과가 달라질 수 있다.

실험 실행과 전체 보고서는 작업공간 루트의 `scripts/myeongdong_hypotheses.py`, `scripts/report_myeongdong_hypotheses.py`, `output/myeongdong-hypotheses/demo-20261031-a/`에 있다.

## 구성과 데이터 계약

- `scripts/prepare_myeongdong_5044.py`: 원본 OSM과 지도·합성 인물에서 독립 입력 번들과 출처·가정을 생성한다. 최신 Rust fixture로 생성한 개발 정의의 `--fixture-root`가 필요하다.
- `scripts/myeongdong_ui_server.py`: 조건을 별도 번들에 적용하고 Rust 빌드·실행과 실제 결과 요약을 로컬 API로 연결한다. 실행별 입력·출력은 `sim/runs/ui_jobs/<id>/`와 `public/runs/<id>/`에 남는다.
- `sim/crates/mdsim-runtime/examples/replay_myeongdong_5044.rs`: 각 인물을 직접 도착시켜 실제 `Sim`과 `FileSink`로 실행한다. 10분 프레임이 완성될 때마다 `run_status.json`을 원자적으로 갱신하며, 종료 시 엔진 결과와 manifest를 기록한다.
- `src/engine/client.ts`, `useEngineRun.ts`, `frames.ts`, `replay.ts`, `agents.ts`, `useReplay.ts`: 14바이트 `mdsim-frames-v1`을 지연 해석하고, 해시 검사한 조각 최대 2개를 캐시해 Three.js에 표시한다. 예시 보행과 매출은 사용하지 않는다.
- `source.json`: 원본 자료 해시와 공간 통계, 좌표 변환, 가정. `manifest.json`에는 엔진 기록과 프레임 해시가 있다.

## 좌표·건물 ID 대조

GLB 건물 1,252개와 정본 지도 건물 709개 중 663개가 공통이다. 이 공통 건물의 4,014개 고유 외곽점을 검증한 결과, 축별 선형 변환 후 외곽까지 거리의 95백분위는 약 **0.083m**, 최댓값은 약 **0.122m**다. 변환하지 않은 건물 중심의 중앙 오차는 약 147.53m다. 실행의 변환과 GLB 해시가 맞아야 프레임을 표시한다.

이 비교는 공통 건물 외곽의 수평 정합에 한정된다. 보도·비공통 지역·지면 고도는 검증하지 않았으며 GLB 지면은 평면이다. 감사는 `python3 scripts/audit_myeongdong_ui_coordinates.py`, 테스트는 `python3 -m unittest discover -s tests -p test_myeongdong_ui_coordinate_audit.py -v`로 실행한다.

## 시나리오 입력과 검증

`scripts/myeongdong_scenarios.py`는 원본 번들을 보존하고 실행별 도로·장소·프로필을 변경한다. `scripts/myeongdong_buildings.py`는 GLB와 정본 지도 ID를 매칭해 건물별 장소를 생성한다. 각 입력의 해시와 가정은 실행별 manifest와 source에 기록된다. 업종 기본값, 노점 배치와 벤치 배치는 모델 가정이며 실제 상점 기록이 아니다. 5,044명 직접 입장, 건물별 장소 연결 및 결과 사건 합계는 Rust 실행과 대조한다.

이전 두 조건만 기록한 실행도 열 수 있다. 이 실행에는 노점과 추가 변수의 새 기준이 적용되지 않았으므로 결과에 별도로 표시한다. 새로 계산하면 현재 선택한 전체 조건이 적용된다.
